# 文风验收

## 使用方式

先检查证据与对象，再检查结构与表达。以下为默认工作约定；用户明确的目标和格式优先。只验本次任务适用项，不为局部任务扩张工作范围。

## 规则

| 规则 | 通过标准 | 不通过的表现 | 最小修改 |
| --- | --- | --- | --- |
| W01 工作文风 | 直接说事实、判断、原因和动作；语气平实、克制 | 花哨开场、情绪渲染、连续设问、金句取代信息 | 删除修辞，保留对象、动作与结果 |
| W02 信息层级 | 概括短；解释补足理解；细节和原话放在对应列或引用 | 概括栏复制整句评论；正文到处重复同一证据 | 先决定该句承担概括、解释还是举证，只保留一种主要任务 |
| W03 清楚指代 | 不看前文也能知道谁、什么产品、哪个动作或接口 | “这种键”“别占接口”“语音和一键就够” | 回到来源补齐对象；无证据不能自行脑补 |
| W04 保留差异 | 缩短后仍保留决定用法的条件和结果 | 把按一下/按两下写成“便捷切换”；把进入输入框写成“执行” | 保留手势、目标、反馈、限制；删掉泛化形容词 |
| W05 按目的取舍 | 当前问题相关的信息优先，背景简带 | 竞品功能调研大篇讲生态商业化；把明确不对外写的背景塞进正文 | 删除越界背景，必要成本一句交代 |
| W06 一句一主张 | 一句能指出明确事实或判断，解释紧跟其后 | 同句混入成本、兼容、体验和方案；靠多重括号补丁 | 拆开主张，再按模块放回正确位置 |
| W07 删除空话 | 每句话增加一个事实、差异、理由或行动 | “赋能高效工作”“打造极致体验”“值得关注的是”等没有后续实义 | 改成具体动作；不能增加信息就删掉 |
| W08 结论先行 | 读者先看到要点，再按需看证据 | 先罗列平台、赞数、时间故事，最后才说问题 | 评论写“总结：”和编号要点，表中保留原话与出处 |
| W09 证据不过度 | 样本观察、产品事实、设计建议分开 | “有人提出”写成“用户都需要”；偏好写成已验证付费意愿 | 限定样本与情境；推测保留假设状态 |
| W10 跨章节一致 | 同一纠错应用到所有同类段落；同词同义 | 只把 样例产品A 改短，后续产品仍长；只删第一张表后的重复清单 | 按产品清单逐项检查，改明细后同步总结 |
| W11 术语按理解成本解释 | 保留有用术语，在首次出现时解释具体行为 | “急停”“回传”“hooks”“续写”只有词，没有对象和作用范围 | 解释停止哪个任务、回传什么、由谁执行；技术细节只写影响判断的部分 |
| W12 不机械压字数 | 以删重复、保留差异来精简；一短句不够时可补一完整句 | 为“短”删掉因果、对象和前提；规定所有概括必须四字 | 优先可理解，再压缩；不强制固定字数或每节条数 |

## 完成判定

- 通过：本次适用项满足，关键结论能回到材料。
- 需修改：有材料可修，先做局部修订并同步受影响结论。
- 待核或待决定：说明具体缺口及影响，不能通过润色或自评分掩盖。

结构检查不能证明事实真实。产品定义的讨论稿通过不代表用户已经确认方案。只汇报发现的问题和重要未决项。
