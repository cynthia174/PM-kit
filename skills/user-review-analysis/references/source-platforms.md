# 评论来源平台建议

平台是取证入口，不是固定必查清单。根据产品类型、目标用户、研究问题、地区和可访问性选择来源；主动收集时尽量组合两类以上来源，避免只依赖单个平台。

## 来源类型

| 来源类型 | 示例 | 适合确认什么 | 使用边界 |
| --- | --- | --- | --- |
| 官方网站购买页 | 产品官网购买页、官方商城、官方产品详情页 | 产品名称、型号、版本、价格、套餐、规格、购买入口和官方定位 | 不能把产品介绍、官方宣传语或购买页本身当作用户评论；购买页上的真实用户评价需要单独识别 |
| 电商评价 | Amazon、京东、淘宝、天猫及其他销售平台的商品评价 | 买家使用体验、价格感受、质量、售后和购买后的问题 | 区分买家评价、问答、晒单、商家回复和平台评分；评分口径与评论原文分别记录 |
| 应用/软件评价 | App Store、Google Play、Chrome Web Store、GitHub Issues 等 | 安装、稳定性、功能使用、兼容性、版本问题和功能请求 | GitHub Issue 可能是开发者、维护者或用户报告，不能一律当普通买家评论 |
| 社区讨论 | Reddit、知乎、V2EX、Discord、产品论坛等 | 使用场景、替代比较、长期体验、问题讨论和需求表达 | 区分亲自使用、转述、提问、猜测和围观；Discord 私密或临时内容需确认授权和可引用范围 |
| 视频和内容平台 | B站、YouTube、小红书、X 等 | 实际演示、上手体验、比较观点和评论区反馈 | 视频作者身份、演示材料和评论区用户要分开；只看标题或封面不能生成评论 |
| 官方反馈渠道 | 产品社区、官方论坛、客服公开回复、功能请求页 | 官方对问题的回应、功能请求、已知限制和处理状态 | 官方回复不等于用户体验；功能请求不等于已实现能力或普遍需求 |
| 专业评测 | 媒体评测、博客、长视频评测 | 系统化体验、横向比较、测试条件和专业观察 | 评测是专业作者观点，不直接等于普通用户评论；保留作者、测试条件和发布日期 |

## 收集和记录规则

1. 先用官方网站购买页确认产品对象、型号、版本、价格和购买入口，再到适合的评论或讨论平台收集用户原话。
2. 来源字段写到具体页面、帖子、视频、Issue 或商品评价入口；平台首页只能作为导航，不能替代具体证据。
3. 记录来源性质，例如买家评价、应用评分、社区讨论、视频作者体验、评论区回复、官方回应或专业评测。
4. 价格、评分、点赞、发布时间和库存状态都可能变化，记录采集时间和必要的地区/版本条件。
5. 不同平台的点赞、评分和评论数量不能直接相加，也不能据此推导市场比例、代表性或付费意愿。
6. 用户限定只用已有材料时，不主动补充外部平台；无法访问或未实际阅读的页面标为待核，不编造原文。
