# 软件能力与连接范围比较

## 先定义同一动作

“会话管理”应拆成创建、恢复同一会话、基于历史另开会话、切焦点、归档等实际动作。“语音”应拆成录音、转写、放进输入框、发送和开始执行。不同产品只有相同动作才直接对比。

## 能力归属

| 层次 | 要核对的内容 | 常见误判 |
| --- | --- | --- |
| 硬件 | 按键、麦克风、屏幕、连接与反馈 | 有麦克风就当成已经集成某AI应用 |
| 宿主应用 | 当前版本实际提供的动作 | 应用有功能就当作外设能调用 |
| 官方集成 | 官方文档明确支持的设备和接口 | 宣传“官方合作”就推断全部权限 |
| 公开开发接口 | 可由第三方开发实现的动作和限制 | 接口理论上可做就写成成品已实现 |
| hooks/事件 | 发出什么事件、可否返回控制响应 | 收到状态通知就等于能够审批/续接 |
| 插件/桥接 | 安装条件、代码/文档证明、维护状态 | 非官方桥接当成稳定公开API |
| 宏/模拟操作 | 快捷键、焦点要求、是否依赖UI | 能模拟按钮就当成稳定后台控制 |

每项重要能力记录：`动作｜宿主/平台/版本｜产品当前实现｜集成路径｜依赖与限制｜具体出处｜核查日期`。源码可证明实现路径，但运行稳定性还需要实际验证。

## 连接与离座

分别比较电脑旁无线、同网络、跨网络；再检查离开电脑后能做什么、看见什么、怎样确认。屏幕可能只显示状态、列表或转写文本，不等于完整画面回传。

## 矩阵符号

- ✓：证据明确的原生能力。
- 插件✓：安装指定插件后具备，注明插件与平台。
- △：需要用户自行映射或开发，说明程度。
- —：有依据确认不具备。
- ?：材料不足、型号不明或尚未查到。

用户要简表时保留上述条件的短注；不要用符号删掉决定结果的限制。
