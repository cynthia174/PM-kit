# 竞品调研验收

## 使用方式

先检查证据与对象，再检查结构与表达。以下为默认工作约定；用户明确的目标和格式优先。只验本次任务适用项，不为局部任务扩张工作范围。

## 规则

| 规则 | 通过标准 | 失败时处理 / 典型问题 |
| --- | --- | --- |
| C01 范围 | 总览、单品、对比、结论中的产品名单和版本一致；新增竞品按现有有效维度纳入 | 对照产品清单修漏项，不暗换型号 |
| C02 权重 | 主要篇幅用于功能、交互、特别之处和用法；商业化、生态、订阅只保留影响判断的事实 | 删无关分析；明确不入正文的内部背景不得写出 |
| C03 单品开头 | 小标题下有1—2个产品链接；先短说最大特点和价格，再讲形态/用法 | 调整位置，删除无服务费时的空字段 |
| C04 动作清楚 | 核心功能说明操作什么、怎样操作、作用于谁、结果在哪里 | 将“高效”“智能”改为动作；不能靠猜补流程 |
| C05 条件保真 | 按下/按住/双击/松开、前台/后台、转写/发送/执行等区别清楚 | 回到资料补清；不能缩写成一个含糊动词 |
| C06 默认与扩展 | 默认动作、可配置动作、插件和自编脚本分开；说明必要软件是否后台常驻 | 修正“开箱即有”的错误归因 |
| C07 局部完整 | 用户要求列全的功能/预设必须逐项覆盖，可分组但不能用“等”藏缺项 | 对照官方清单检查；未说明项标为未查清 |
| C08 关键配置 | 保留影响使用的硬件、软件、麦克风来源、连接、平台和反馈方式 | 删除无关参数，补会改变结论的依赖 |
| C09 同系列区别 | 基础款、联名款、软件模式分别描述，不借用另一版本能力 | 在相关句和表格加型号/模式限定 |
| C10 比较同题 | 每行回答同一问题，如状态如何显示、审批如何执行、语音发到哪里 | 不同问题拆行，不拼接各家宣传语 |
| C11 能力与未知 | 原生/插件/映射/已确认不具备/未确认分开；只比较当前有证据的范围 | 缺证改“?”，禁止把搜不到等同于没有 |
| C12 远程边界 | 区分近距离无线、家庭网络、跨网络；说明是否仍看电脑、设备端可见内容、软件依赖 | 不用“有Wi-Fi”直接推断效果最好，不把蓝牙一概写成不能离座 |
| C13 软件归属 | 区分宿主能力、官方集成、公开API、hooks、插件/桥接、宏；事件通知不等于动作控制 | 将“公开接口可实现”与“成品已支持”拆开 |
| C14 结论成立 | 每条结论点名比较维度与支撑产品，说明差异及意义；与表格无矛盾 | 删“全部/唯一/标配”等超范围断言，补条件 |
| C15 借鉴具体 | 独特设计说明怎么用、少做了哪一步或增加了什么反馈 | 不把“有旋钮”“有屏幕”单列成价值结论 |
| C16 素材有效 | 少量视频确实对应所述动作；优先最简洁能说明用法的版本；没有对应视频可用相关图片 | 仅外观宣传/开箱不能证明语音反馈或会话操作；不为凑数量插素材 |
| C17 出处可靠 | 每项关键事实可追溯；价格/版本/插件状态附必要时间和适用范围；素材来源单独可达 | 首页只能作产品入口，不能代替具体说明出处 |
| C18 全文同步 | 修改某型号/功能后，更新总览、单品、比较、结论；同类纠错覆盖所有产品 | 用清单检查，不能仅改用户举例的第一处 |

## 完成判定

- 通过：本次适用项满足，关键结论能回到材料。
- 需修改：有材料可修，先做局部修订并同步受影响结论。
- 待核或待决定：说明具体缺口及影响，不能通过润色或自评分掩盖。

结构检查不能证明事实真实。产品定义的讨论稿通过不代表用户已经确认方案。只汇报发现的问题和重要未决项。
