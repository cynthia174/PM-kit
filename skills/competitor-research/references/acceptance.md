# 竞品分析验收

## 使用方式

先检查研究对象、证据和比较问题，再检查结构、结论和表达。以下是适用于软件、硬件、服务、平台及组合产品的通用标准；用户明确的目标、材料范围和交付格式优先。只检查本次任务适用的项目，不为了凑齐规则扩张研究范围。

## 规则

| 规则 | 通过标准 | 失败时处理 / 典型问题 |
| --- | --- | --- |
| C01 研究范围 | 明确研究目的、产品名单、版本/方案范围和资料边界；总览、单品、对比、结论中的对象保持一致 | 补齐或删除范围外对象；不暗换版本、套餐或比较口径 |
| C02 研究重点 | 篇幅主要服务于本次选择问题：功能、体验、流程、差异和使用价值；背景、商业化、生态等只保留会影响判断的内容 | 删除与决策无关的展开；不把内部动机写成对外结论 |
| C03 单品信息 | 每个对象先给一句定位或最大特点，再说明本次相关的价格/成本、主要能力和适用范围；信息顺序便于快速浏览 | 把规格堆在开头；缺少定位或把无关参数当重点 |
| C04 使用流程 | 关键能力写清用户从哪里进入、做什么、系统如何响应、结果在哪里出现；读者能据此理解基本用法 | 将“智能、方便、效率高”等宣传语改成可观察的步骤；资料不足时标待核 |
| C05 关键差异 | 保留会改变选择或使用结果的条件、步骤、角色、限制和反馈；相近说法不能抹平重要差异 | 回到资料补充前提；不要用一个宽泛动词替代多个不同动作 |
| C06 能力层级 | 需要时区分现成能力、配置后能力、第三方扩展、理论可实现能力和未确认能力；不适用的层级可以省略 | 修正把可能做到写成已经具备的表述；缺证据标为未确认 |
| C07 局部完整 | 用户要求列全的功能、流程、方案或版本差异逐项覆盖；可以分组，但不能用“等”隐藏遗漏 | 对照用户清单逐项补齐；无法确认的项目明确列出缺口 |
| C08 关键条件 | 只保留会改变体验、结果或结论的前置条件，例如账号、权限、平台、地区、数据、费用、角色或服务依赖 | 删除无关规格；补充会改变结论的依赖和限制 |
| C09 版本与对象边界 | 不同型号、套餐、地区、用户角色、软件模式或服务层级分别描述；一个对象的能力不能借给另一个对象 | 在句子、表格和链接旁补对象限定；拆分混写的内容 |
| C10 比较同题 | 对比表每行回答同一个问题，使用相同维度和相近粒度；各对象的证据都能对应这一问题 | 拆开不同问题；不要把各家宣传语拼成貌似可比的一行 |
| C11 证据与未知 | 区分已观察、官方说明、用户反馈、推断、建议和未确认；“没有找到”不能直接等于“不存在” | 降低断言强度；补来源或保留待核状态 |
| C12 使用边界 | 说明产品在哪些环境、流程、角色或任务中有效，以及哪里需要额外条件；不要从单一特征推导完整体验 | 补充适用范围和限制；删除超出材料的场景推断 |
| C13 实现归属 | 涉及组合产品或集成时，说明能力由哪个产品、服务、账号、接口或第三方环节提供；集成可能性不等于成品现状 | 拆开产品本身和外部依赖；将“可以实现”与“已经支持”分开 |
| C14 结论成立 | 每条结论明确比较维度、涉及对象、证据和对选择的意义；结论与正文、表格没有矛盾 | 删除“最好、唯一、全部”等无依据断言；补条件或改成待验证判断 |
| C15 借鉴具体 | 提炼可迁移的设计或服务做法，说明它如何被使用、减少了什么成本或增加了什么价值 | 不只罗列特征；把“有某功能”改成可理解的使用价值 |
| C16 素材有效 | 图片、视频、演示或截图确实支持相邻文字中的对象、流程或差异；素材用途和观看/核验状态清楚 | 移除只展示外观或无法证明结论的素材；未核验的内容标为候选 |
| C17 出处可靠 | 关键事实、价格、版本、案例、用户反馈和素材有可追溯出处，并注明必要的时间、地区或适用范围 | 用具体页面替代泛入口；补来源信息或降低结论强度 |
| C18 全文同步 | 修改对象、事实或比较口径后，总览、单品、对比、结论、目录和引用同步更新；同类问题在全文一致处理 | 用对象和规则清单回查全文，不只修用户指出的第一处 |

## 完成判定

- 通过：本次适用项满足，关键事实和结论可以回到材料。
- 需修改：已有材料足以修正，先完成局部修改并同步受影响内容。
- 待核或待决定：说明缺口、影响和下一步核验方式，不能用润色或自评分掩盖。

结构检查不能证明事实真实、样本具有代表性或外部链接长期有效。竞品分析通过也不等于自家产品方案已经确定。
