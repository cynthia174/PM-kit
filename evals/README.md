# 行为评测

[cases.json](cases.json) 中所有产品、评论和链接都是合成测试材料，不是市场事实。每个案例有实际请求、触发正例/反例和可观察检查点。

1. 使用新会话，只提供目标 Skill 路径和该案例的 `request`。允许读取该 Skill 自带资源；关闭联网和外部写入。不要把 `checks` 当作提示词给执行者。
2. 保存实际输出，再由评审逐项对照 `checks`，记录通过、失败或无法判断及证据。出现虚构来源、篡改原话或将建议写成已确定，视为关键失败。
3. 单独用 `positive_triggers` / `negative_triggers` 在目标客户端观察选择结果。显式指定 Skill 的执行测试不证明自动触发可靠。
4. 修订规则后重跑失败案例及相关模块；不要只匹配某一句标准答案。

本地执行记录可放在忽略的 `evals/runs/` 中。公开记录只保留匿名摘要，见 [验证记录](../docs/validation.md)。这四个案例是初始回归集，不代表覆盖所有领域、语言或长文档。
